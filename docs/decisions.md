# 技术决策记录（ADR）

记录重要技术选择，避免几个月后忘记“为什么当时这么定”。

## 模板

```markdown
## YYYY-MM-DD 决策标题

- 状态：提议 / 已采纳 / 已废弃
- 背景：
- 备选方案：
- 决定：
- 原因：
- 代价 / 风险：
- 何时重新评估：
```

## 2026-11-08 使用 Unity URP 作为主引擎

- 状态：已采纳
- 背景：需要采集低分辨率颜色、深度、运动矢量，并做实时 demo。
- 备选方案：Unity URP、Unreal Engine 5、自写 OpenGL/Vulkan 渲染器。
- 决定：主线使用 Unity URP。
- 原因：
  - C# 上手快，单人迭代快。
  - URP 自定义 Render Feature 足够做数据采集。
  - 4060 Laptop 8GB 跑 Unity 比 UE5 舒服。
- 代价 / 风险：
  - 引擎底层细节不如 Unreal 完整。
  - 后期如果走图形学/AAA 方向，需要补 Unreal。
- 何时重新评估：D 原型完成后，或明确转向 Unreal 渲染方向时。

## 2026-11-08 Windows 作为训练主机器，Mac 作为文档/规划机

- 状态：已采纳
- 背景：Mac 为 A18 Pro / 8GB 统一内存；Windows 为 RTX 4060 Laptop / 32GB。
- 决定：
  - Windows：训练、Unity、TensorRT、实验。
  - Mac：规划、文档、周报/月报、代码审阅。
- 原因：训练代码必须在 GPU 机器上边跑边调；Mac 内存不足。
- 代价 / 风险：两台机器需要严格 Git 同步。
- 何时重新评估：不需要，除非换机器。

## 2026-11-08 仓库命名为 DLSS，但明确免责声明

- 状态：已采纳
- 背景：项目受 DLSS 启发，但不是 NVIDIA DLSS 的复刻。
- 决定：仓库名 `DLSS`；README 第一段写清“学习项目、非官方、不隶属 NVIDIA”。
- 原因：名字直观，便于检索；免责声明避免误导。
- 代价 / 风险：可能与 NVIDIA 商标混淆；不使用 NVIDIA logo、SDK 或商业素材。
- 何时重新评估：项目公开推广前。

## 2026-11-08 先做 D，再做 E

- 状态：已采纳
- 背景：D（时序超分）是复试主线；E（帧生成）风险更高。
- 决定：第 7–15 个月做 D；第 16–18 个月做 E 简化版。
- 原因：D 的可演示性更稳；E 需要光流、遮挡和延迟控制。
- 代价 / 风险：E 可能时间不足。
- 何时重新评估：第 12 个月 gate。

## 2026-11-08 初始范围：2x，540p → 1080p

- 状态：已采纳
- 背景：8GB 显存，20 个月周期，单人开发。
- 决定：先做 2x，不碰 4x；先做 540p 输入，不碰 4K。
- 原因：降低数据、显存和训练成本。
- 代价 / 风险：演示效果不如 4x 惊艳。
- 何时重新评估：D 稳定后，视时间和显存决定是否做 4x。
