## 2026-11-08 使用 Unity URP 作为主引擎

- 状态：已采纳
- 背景：需要采集低分辨率颜色、深度、运动矢量，并做实时 demo。
- 备选方案：Unity URP、Unreal Engine 5、自写 OpenGL/Vulkan 渲染器。
- 决定：主线使用 Unity URP。
- 原因：
  - C# 上手快，单人迭代快。
  - URP 自定义 Render Feature 足够做数据采集。
  - 4060 Laptop 8GB 跑 Unity 比 UE5 舒服。
- 代价 / 风险：
  - 引擎底层细节不如 Unreal 完整。
  - 后期如果走图形学/AAA 方向，需要补 Unreal。
- 何时重新评估：D 原型完成后，或明确转向 Unreal 渲染方向时。

## 2026-11-08 Windows 作为训练主机器，Mac 作为文档/规划机

- 状态：已采纳
- 背景：Mac 为 A18 Pro / 8GB 统一内存；Windows 为 RTX 4060 Laptop / 32GB。
- 决定：
  - Windows：训练、Unity、TensorRT、实验。
  - Mac：规划、文档、周报/月报、代码审阅。
- 原因：训练代码必须在 GPU 机器上边跑边调；Mac 内存不足。
- 代价 / 风险：两台机器需要严格 Git 同步。
- 何时重新评估：不需要，除非换机器。

## 2026-11-08 先做 D，再做 E

- 状态：已采纳
- 背景：D（时序超分）是复试主线；E（帧生成）风险更高。
- 决定：第 7–15 个月做 D；第 16–18 个月做 E 简化版。
- 原因：D 的可演示性更稳；E 需要光流、遮挡和延迟控制。
- 代价 / 风险：E 可能时间不足。
- 何时重新评估：第 12 个月 gate。

## 2026-11-08 初始范围：2x，540p → 1080p

- 状态：已采纳
- 背景：8GB 显存，20 个月周期，单人开发。
- 决定：先做 2x，不碰 4x；先做 540p 输入，不碰 4K。
- 原因：降低数据、显存和训练成本。
- 代价 / 风险：演示效果不如 4x 惊艳。
- 何时重新评估：D 稳定后，视时间和显存决定是否做 4x。

## 2026-11-18 M0 数据源先用 scikit-image 示例图，不引入 BSDS500/DIV2K

- 状态：已采纳（临时，M1 前重新评估）
- 背景：M0 目标是跑通 SRCNN baseline，验证"数据→训练→PSNR"这条链路，
  不想在第一天就花时间下数据集、写下载脚本、处理大数据。
- 备选方案：BSDS500（经典 SRCNN 数据集，需下载）、DIV2K（大，需注册）。
- 决定：用 `skimage.data` 自带的 10 张真实照片/纹理（astronaut、chelsea、coffee、
  rocket、camera、grass、gravel、brick、clock、immunohistochemistry），
  首次读取时缓存成 `.npy` 到 `$DLSS_DATA/cache/skimage`。
- 原因：
  - 完全离线、可复现，换机器不用重新下载。
  - 内容够杂（人像、静物、纹理），x2 bicubic 的 Y-PSNR 从 23.7 到 37.4 dB，
    有区分度，不是自欺欺人的简单样本。
- 代价 / 风险：
  - 只有 10 张图，train 8 / val 2，指标方差大，不能拿去和论文数字比。
  - 与公开 benchmark 不可比。
- 何时重新评估：M1 开始时换 BSDS500 / DIV2K，这套数据保留作快速冒烟测试。
  判定标准：换真实数据集后结论方向一致。

## 2026-11-18 SRCNN baseline 的三个口径：Y 通道、bicubic 输入、残差预测

- 状态：已采纳
- 背景：需要一套"和 bicubic 公平比较"的最小 baseline。
- 决定：
  1. 训练和评估都只在 **Y 通道**，色度用 bicubic 上采样后拼回（超分领域通行口径）。
  2. 网络输入是 **bicubic 上采样后的 LR**，这样输入相同，任何 PSNR 提升只能归因于网络。
  3. 网络**预测残差**（输出 = 输入 + net(x)），最后一层卷积零初始化，
     所以训练开始那一刻模型输出严格等于 bicubic。
- 原因：第 2、3 点让"是否超过 baseline"变成可证伪的命题；第 1 点让数字能和文献对照。
- 代价 / 风险：
  - 输入已是双三次插值，网络只学高频修正，天花板受 bicubic 限制（M0 可接受）。
  - 只算 Y-PSNR 会掩盖色度误差；M2 起补 LPIPS 和 RGB 指标。
- 何时重新评估：M2 做真正的时序超分时，输入端改为 LR + 运动矢量。

## 2026-11-18 训练按 iteration 计，不按 epoch

- 状态：已采纳
- 背景：patch 在线随机采样，10 张图不存在"一个 epoch 遍历一遍"的自然含义。
- 决定：配置写 `train.iters`，每 `val_every` 步在验证集整图上算 PSNR，按 best 存权重。
- 原因：迭代数直接对应算力和时间，实验之间更好对齐。
- 代价 / 风险：不同 patch/批量下 iters 不可直接比较，需同时记录吞吐。
- 何时重新评估：数据量大到需要严格 epoch 语义时（M1 换数据集后）。
